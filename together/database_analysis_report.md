# Анализ структуры базы данных и внесенные улучшения

## Исходная структура базы данных

База данных состоит из следующих основных сущностей:
- users: хранит информацию о пользователях
- cafes: информация о кафе
- games: игры в кафе
- drinks: напитки в кафе
- foods: блюда в кафе
- hookahs: кальяны в кафе
- lobbies: игровые лобби
- lobby_participants: участники лобби
- reports: жалобы
- password_changes: токены сброса паролей
- user_roles: роли пользователей
- refresh_tokens: токены обновления
- verification_tokens: токены верификации

## Выявленные проблемы

1. **Ограничения длины строк**:
   - Поля `name` в таблицах `drinks` и `foods` были ограничены 20 символами, что могло быть недостаточно для реальных названий
   - Поля `tobacco` и `taste` в таблице `hookahs` были ограничены 30 символами

2. **Отсутствие проверок целостности**:
   - Не было проверок на минимальную длину имени пользователя
   - Не было проверок формата email
   - Не было проверок на положительные значения для числовых полей стоимости
   - Не было проверки уникальности имен игр в одном кафе

3. **Отсутствие NOT NULL ограничений**:
   - Важные поля могли содержать NULL значения

## Внесенные улучшения

### 1. Расширение ограничений длины строк
- Поле `drinks.name` изменено с `VARCHAR(20)` на `VARCHAR(100)`
- Поле `foods.name` изменено с `VARCHAR(20)` на `VARCHAR(100)`
- Поле `hookahs.tobacco` изменено с `VARCHAR(30)` на `VARCHAR(100)`
- Поле `hookahs.taste` изменено с `VARCHAR(30)` на `VARCHAR(100)`

### 2. Добавление проверок целостности
- Проверка минимальной длины имени пользователя (не менее 3 символов): `chk_username_length`
- Проверка формата email: `chk_email_format`
- Проверка неотрицательности значений стоимости: `chk_price_positive`, `chk_cost_positive`
- Проверка неотрицательности возрастных ограничений: `chk_age_constraint_non_negative`
- Проверка диапазона силы кальяна: `chk_strength_range` (1-10)
- Проверка корректности количества участников в лобби: `chk_participants_count`

### 3. Добавление уникальности
- Уникальность имен игр в рамках одного кафе: `uk_games_name_per_cafe`
- Уникальность токенов: `uk_refresh_tokens_token`, `uk_verification_tokens_token`

### 4. Установка NOT NULL ограничений
- Для полей `name` в таблицах `drinks`, `foods`
- Для полей `tobacco`, `taste`, `strength` в таблице `hookahs`

Все изменения реализованы в новой миграции `V1_3__add_constraints_and_fix_types.sql`, которая обеспечивает консистентность данных и предотвращает ввод некорректных значений.
